# P2 · Names: labels and book registry (B0)

**Lane:** Python (the bridge's vocabulary) + TypeScript (labels). **Deploys:**
none (no worker code path changes; P6 is the first caller). **Needs:** P1
(the registries it extends), the operator's green light.
**Goal:** every price the scraper holds can be named the way the app names
it: its market (props and game markets), its book, and whether it is a price
at all.

---

## What the census found (2026-09-24, `data/vocab-2026-09-24.json`)

Read-only census of the scraper DB (`data/census_scraper_vocab.py`): the
2 h of offers before the stall, plus every prop market first seen that day.

| | measured |
|---|---|
| Prop markets (`prop_markets.stat`) | **313 labels**, 4,584,163 markets in one day |
| …resolved by the app's alias map today | **8.7%** (comparenbet's `player_*` names dominate: `player_touchdowns` 1.66M, `player_reception_yds` 744k, `player_rush_yds` 438k, …) |
| …resolved by this spec's map | **99.8% mapped + 0.1% position-dependent (resolved at bridge time)**; 13 labels (~1,000 rows/day) wait for a sample check (§2) |
| Game markets (`offers.market`, no prop id) | **251 strings**, 323,985 rows in 2 h |
| …parsed by this spec's grammar | **96.9%**; the other 3.1% are `prop`/`player_*` rows filed as game offers, which are not game markets |
| Book keys (`offers.book_key`) | **98**; 83.4% of rows already use an app canonical key |

The full per-label mapping is **`data/scraper_prop_labels.csv`** (source,
label, rows, key, rule, status), and the full game-market table is
**`data/scraper_game_markets.csv`** (market, rows, period, type, status).
Both are generated by **`data/gen_scraper_market_map.py`**. Its dictionaries
*are* the decisions; this phase ports them into the app.

**Two corrections to the plan's B0**, both from the data:
1. **Only Python needs the scraper's vocabulary.** The bridge (P6) writes
   canonical keys, and TypeScript never sees a scraper label. So the scraper
   map lives in **one Python module**. Only the **new canonical keys** go
   into both alias maps, as identity aliases, so labels and the drift test
   know them. The plan said "add every label to both maps", which would have
   put about 300 scraper spellings into TypeScript for no reader.
2. **Some labels mean different things by source and by player.**
   "Strikeouts" is pitcher strikeouts at Pinnacle, DraftKings and 4codds but
   batter strikeouts elsewhere, and the app's global map sends `strikeouts`
   to `batter-strikeouts`. So the map is **source-scoped first**, and the
   MLB labels `strikeouts`, `walks` and `hits` resolve from the matched
   player's roster position (P3): a pitcher gets the pitching key, anyone
   else the batting key, and a two-way player (`TWP`) stays unresolved,
   never guessed.

2. Map the label if the meaning is certain; otherwise mark it `skip` with the
   reason.
3. Record each decision in the generator (`MANUAL` or a new `SKIP` set) with
   a one-line comment naming the evidence.

### 3. `python-odds-service/src/scraper_markets.py` (new)

A pure module (no DB, no network), ported **verbatim** from the generator's
dictionaries:
- `NEW_KEYS`, `PERIOD_PREFIX`, `MANUAL`, `SOURCE_MANUAL`,
  `POSITION_DEPENDENT`, `NOT_PLAYER_PROP`, `NO_APP_SPORT_PATTERNS` and the
  `VERIFY` outcomes from §2;
- `GAME_PERIOD` and `GAME_TYPE`.

Public API:

```python
PITCHER_POSITIONS = frozenset({"P", "SP", "RP"})
TWO_WAY_POSITIONS = frozenset({"TWP"})

def prop_market_key(source: str, label: str, position: str | None = None) -> str | None:
    """The app market key for a scraper prop label, or None (unmapped, verify, skip,
    no app sport, team market). `position` is the matched roster position (P3); a
    POSITION_DEPENDENT label with no position, or a two-way player, returns None."""

def prop_label_status(source: str, label: str) -> str:
    """mapped | position | verify | skip | no-app-sport | not-a-player-prop | unmapped:
    what the bridge reports for a row it did not write."""

def game_market(market: str) -> tuple[str, str] | None:
    """(period, type) for a scraper game-market string, or None. period: fg, 1h, 2h,
    1q..4q, p1..p4, f3, f5, f7, i1..i9, s1, m10, live. type: ml, sp, tot, ml3, tt_home,
    tt_away, tt, odd_even, btts, ... (the GAME_TYPE values)."""

NON_PRICE_BOOKS = frozenset({"comparenbet_fair", "anconsensus", "anopen"})
UNIDENTIFIED_BOOKS = frozenset({"4c", "4cx", "apex", "3et", "sharpbookc", "sharpag", "sharpbet",
                                "amapola", "vertex", "buckeye", "predictfun", "playersfantasy", "pph", "hard"})

def bridgeable_book(book_key: str | None) -> bool:
    """False for None, a NON_PRICE_BOOKS row (a consensus or opener line, never a
    sportsbook price; anopen feeds openers in P5, not prices) and an UNIDENTIFIED_BOOKS
    code (kept on the laptop until identified)."""
```

`normalize` is the generator's `norm()`: lowercase, `&` → `+`, collapse
whitespace and underscores.

### 5. Period props in labels — `lib/odds/props/marketLabels.ts`

`marketLabel(key, sport)`: a key matching
`^(1h|1q|1i|1s)-(.+)$` → `"<period label> · <base label>"`, with period
labels `1h` "1st half", `1q` "1st quarter", `1i` "1st inning", `1s` "1st
set". The base goes through the normal lookup. So `1h-receptions` →
"1st half · Receptions".

### 7. Tighten the drift test

`tests/config-drift.test.ts`, the market test: also assert
**the canonical value sets are identical**:
`new Set(ts.values())` equals `new Set(py.values())`. Today it only checks

silently. The key sets stay allowed to differ, since each language has
provider-specific spellings.
