# P5.1 · Hardening: the corpus export gap and three tables without RLS

**Lane:** Python (laptop tool + corpus) and one migration. **Deploys:** none
(no worker code changes; the migration is applied by hand). **Needs:** P5.
Runs before P6. Moved here from P5's "found here, not fixed here" by the
operator (2026-09-25).
**Goal:**
- every closed id chunk of every id-chunked corpus table is fully in the
  corpus, and the rule that let chunks close half-exported is fixed;
- every table the app exposes has RLS on.

---

## 1. The id-chunk export gap (`refresh_corpus.py`)

**Measured in P5** (`convert_prop_history.py --legacy-proof`, 2026-09-25):
2,945,086 of `prop_odds_history`'s 7,100,514 rows were in no corpus file. P5
saved them as supplements before dropping the table.

**Cause:** `refresh_corpus.open_partitions` invalidates a chunk's manifest
only while the chunk is still open (`lo + ID_CHUNK_SPAN > max(id)`) at refresh
time. A chunk that fills up between two runs (every 6 h) is already closed at
the next run. Its manifest, written while the chunk was partial and under the
2-hour freeze predicate, is then trusted forever.

**The only id-chunked corpus table left is `mlb_pitch_events`**
(`corpus_store.CORPUS`, `partition_by="id_chunk"`).

Build:
1. **Measure** `mlb_pitch_events` per chunk. Use
   `prune_corpus.verify_partition_live` (verify-only). `live_only > 0` on a
   CLOSED chunk is the gap. Record the counts.
2. **Fix the rule.**
   - The manifest records `max_id_at_export` and `frozen_before` (the freeze
     cutoff it used).
   - A chunk is complete only if `max_id_at_export >= lo + SPAN` and its
     newest row was already frozen at export. Otherwise it is re-exported on
     the next run.
   - A manifest without the new fields counts as incomplete.
   - **A file that holds ids already pruned from Postgres is never
     rewritten.** Rows it lacks go to one disjoint supplementary object per
     chunk (`<name>_final.parquet`), which is read back and verified. This is
     `convert_prop_history.legacy_proof`'s method; generalise it into
     `corpus_store` rather than copying it.
3. **Backfill** the measured gap with that path, then re-run step 1.

Tests:
- `src/test_corpus_chunk_rule.py` (hermetic): the completeness rule on
  synthetic manifests covers open, closed-after-export, closed-before-export
  and missing fields.
- **Live:** after the backfill, verify-only shows `live_only = 0` on every
  closed chunk.

## 2. RLS on `slate_rankings`, `model_status`, `tennis_match_stats`

**Measured 2026-09-25:** `pg_class.relrowsecurity = false` on all three.
- All three are Python-written.
- The app reads them server-side through `pg` (a role that bypasses RLS).

Build: migration `<UTC>_rls_remaining.sql`:
- `ENABLE ROW LEVEL SECURITY` plus one `FOR SELECT USING (true)` policy each
  (the `20260915060000` pattern);
- dry run inside `BEGIN … ROLLBACK`, then applied for real.

Before applying, grep the app for any browser-side (supabase-js) read of
these tables. None is expected; if one exists, the read policy covers it.

Also re-derive the full list: every `public` table with RLS off, from
`pg_class`, not from this spec. Any others are listed, and fixed the same
way in the same migration.

Tests:
- as `anon`: `SELECT` succeeds, `INSERT` fails, on each table;
- the Slate, the model register and a tennis page still render (they read
  through `pg`).

## Exit

- The gap is measured, fixed, backfilled and re-verified at zero.
- The migration is applied.
- `docs/table-ownership.md`'s open item is closed.
- `docs/CURRENT.md` is updated.

## Result

**Closed 2026-09-25 ~05:20 UTC. No deploy: the migration was applied by hand,
and the cron picks up the shared corpus code on push.**

**RLS (migration `20260925040000_rls_remaining.sql`):**
- **20 tables** had RLS off, not 3, re-derived from `pg_class`. The `anon`
  role held INSERT on every one:
  - `athlete_crosswalk`, `game_result`, `index_usage_snapshot`,
    `injury_report`, `job_locks`, `mlb_pitch_events`, `model_status`;
  - `nba_shot_events`, `nfl_target_events`, `nhl_shot_events`,
    `odds_archive`, `odds_import_staging`;
  - `player_history_prefix`, `player_history_summary`, `prop_model_cache`,
    `prop_odds_archive`;
  - `slate_rankings`, `team_name_index`, `tennis_match_stats`,
    `venue_factors`.
- All now have RLS on with one read policy. The migration ends by asserting
  that no public table is left without RLS.
- **Proven as `anon`** (inside rolled-back transactions): SELECT works;
  INSERT is refused; a full DELETE or UPDATE affects 0 rows.
- The app's Supabase clients are used for sign-in only. `/api/model-status`,
  `/api/slate?sport=mlb` and `/api/slate/flags` (MLB, tennis) all return 200.

**The export gap:**
- **Measured:** 10,150 frozen `mlb_pitch_events` rows in closed chunks were in
  no corpus file (chunk 8,000,001: 5,724; chunk 10,500,001: 4,426). Chunk
  16,500,001 had never been exported at all (4,265 frozen rows).
- **Fixed** (`corpus_store`, three rules):
  1. `prune_corpus` never deletes from an open chunk.
  2. A closed chunk already in the corpus is never re-exported;
     `complete_chunk` adds what it lacks as `<chunk>_sNN.parquet`, read back
     and verified. `refresh_corpus` runs it every pass.
  3. Verification reads the main file plus every supplement.
- **Backfilled:** 14,415 rows in 3 supplements.
- **Re-verified:** every closed chunk shows 0 rows missing, and prune
  verify-only now finds all 14,415 provably in the corpus.
- **Found and fixed on the way:** `prune_corpus`'s fingerprint joins values
  with an invisible unit separator (`\x1f`). The copy P5 wrote joined them with `""` (P5's
  legacy proof used it on both sides, so that proof stands; see its note).
  There is now one implementation, `corpus_store.fingerprint`.
- **Tests:** `test_corpus_chunk_rule` (hermetic, in CI).
